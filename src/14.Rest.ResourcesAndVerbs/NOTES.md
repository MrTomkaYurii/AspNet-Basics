# 14. REST: ресурси, дієслова, коди відповідей

## Що демонструємо

Дизайн ресурсів і правильне застосування HTTP-дієслів та статус-кодів.
Окремо — **ідемпотентність** і **безпечність** методів.

## Ключові концепції

### Обмеження REST (Fielding)
1. Клієнт–сервер.
2. **Без стану (stateless)** — кожен запит містить усе потрібне; сервер не
   тримає сесію між запитами.
3. Кешованість — відповідь позначає, чи можна її кешувати.
4. Єдиний інтерфейс — ресурси + стандартні дієслова + представлення (+ HATEOAS, приклад 18).
5. Багатошаровість.
6. Code-on-demand (необов'язково).

### Дизайн URI
- Ресурс — **іменник**, не дієслово: `/products/42`, не `/getProduct?id=42`.
- Колекція — множина: `/products`; елемент — `/products/42`.
- Вкладеність для відношень: `/products/42/reviews`.
- Дії, що не лягають у CRUD, — під-ресурс стану: `POST /orders/42/cancellation`
  (краще, ніж `POST /orders/42/cancel`).
- Фільтри/сортування/пагінація — у query, не в шляху (приклад 16).

### Властивості методів

| Метод | Safe (не змінює стан) | Idempotent (повтор = той самий стан) | Тіло запиту |
|---|---|---|---|
| GET | ✅ | ✅ | — |
| HEAD | ✅ | ✅ | — |
| OPTIONS | ✅ | ✅ | — |
| POST | ❌ | ❌ | так |
| PUT | ❌ | ✅ | так (повне представлення) |
| PATCH | ❌ | ❌ (загалом) | так (опис змін) |
| DELETE | ❌ | ✅ | зазвичай — |

Тому: `DELETE` вже видаленого → `204`/`404`, але **не** `500`. `PUT` двічі
поспіль → однаковий результат. `POST` двічі → **два** ресурси (для захисту —
ключ ідемпотентності `Idempotency-Key`).

### Коди відповідей — мінімум для CRUD API

| Код | Коли |
|---|---|
| `200 OK` | успішні GET/PUT/PATCH з тілом |
| `201 Created` | POST створив ресурс; **обов'язково** заголовок `Location` |
| `204 No Content` | успіх без тіла (DELETE, іноді PUT) |
| `400 Bad Request` | синтаксично невірний запит / помилка прив'язки |
| `401 / 403` | не автентифікований / немає прав (приклад 21) |
| `404 Not Found` | ресурсу немає |
| `405 Method Not Allowed` | метод не підтримується для URI (є `Allow`) |
| `409 Conflict` | конфлікт стану (напр. дубль SKU, застаріла версія) |
| `415 Unsupported Media Type` | `Content-Type`, який сервер не читає |
| `422 Unprocessable Entity` | синтаксис ок, але семантика — ні (варіант для валідації) |
| `500` | непередбачена помилка сервера |

## Спробуйте самі

1. `GET /` — таблиця семантики дієслів.
2. `POST /products` двічі з тим самим тілом → **два** різних `id` (не ідемпотентно).
3. `PUT /products/1` двічі → однакова відповідь обидва рази (version зросте лише
   стосовно вихідного стану; повтор того самого PUT — той самий цільовий стан).
4. `DELETE /products/2`, потім ще раз → `204` обидва рази.
5. `GET /products/999` → `404`. `POST /products/1` → `405` + заголовок `Allow`.
6. `POST /products` із `Content-Type: text/plain` → `415`.
